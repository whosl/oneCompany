项目定位

OneCompany 不是一个预先写好的 AI 应用,而是一个用于验证多 Agent 编排、受治理工具调用和人工 Gate 控制的本地优先交付系统。系统把需求分析 Agent Group、开发 Agent Group、Taizi 调度和 Opencode Harness 串成可观察、可审计、可中断的工作流。

整个过程不是一次性 Prompt。LangGraph 管理宏观工作流、循环预算、状态转换、失败恢复和人工审批;结构化 Agent 承担专业任务;Opencode Harness 驱动真实代码读写与命令执行。所有关键过程形成事件、工具调用、Diff、测试结果与交付产物,用户可实时观察并介入。

双层工作流(职责分离)

把需求确定与开发交付拆成两个职责清晰、通过持久化产物衔接的 Agent Group —— 避免需求未定就编码,也避免单一 Agent 同时承担产品、架构、编码与验收职责。

Taizi(太子)调度 · 与主流并行,不在主流程内

用户任意时刻自由文本 → 三级分类(规则 → LLM → 状态保底)→ 统一入口。

🔍 只读调研
查项目状态/事件/Gate/切片/产物 → 中文回答 · 不改状态
⚡ 调度路由(交互)
暂停 · 恢复 · 插话 · Gate · 变更 · 启动 · 导出 → 改变工作流状态
A2A 协作方式:Taizi 与其他 Agent 不直接对话。调度产出 TaiziDecision,dispatcher 落成调用并发出 taizi.routed 事件;目标 Agent 产出通过统一事件流回流。长耗时动作后台执行,Taizi 立即应答。

开发切片内部循环(单切片)

  1. Planner 拆分功能切片并为每个切片设计测试命令
  2. Opencode Harness 在项目 Git 工作区起本地 server,创建切片会话
  3. 注入 TDD Prompt(目标 + 验收检查 + 测试命令),promptAsync 异步发起
  4. 编码模型真实 ReAct:读文件 / 改文件 / 跑测试 / 看失败 / 修正
  5. OneCompany 独立执行权威测试,解析结构化结果
  6. Review Agent 对照验收标准做只读审查,产出 JSON 裁决
  7. 通过 → Git 提交 → 下一切片;失败 → 重试 / 重规划 / 变更评审
关键防线:Opencode 可以建议代码完成,但只有 OneCompany 自己跑的权威测试通过,LangGraph 才允许切片提交 —— 防住"模型自报成功、伪造测试结果、绕过状态机"。

Agent 清单(共 13 个,统一注册)

每个 Agent 通过注册表声明 id / version / Group / 角色 / 输入输出 Schema / 工具 allowlist / 模型层级 / 风险等级 / 权限。工作流按 agent-id@version 解析 —— 新增、替换、升级 Agent 不需要改架构。

Taizi(太子)调度 Agent · 差异化设计

用户在任意阶段都可能输入任何话——「继续」「停」「加一个导出功能」「为什么 slice failed」——而正确含义取决于当前状态,或需要先查项目事实再回答。Taizi 是这些自由文本的统一入口。

双模式

模式触发行为是否改状态
调度路由继续 / 暂停 / 批准 / 加功能 / 导出 等动作类产出 TaiziDecision,由 dispatcher 落成具体调用是
只读调研status_query / chat调用 8 个只读工具查库/读文件/读事件,再生成中文回答否

13 类意图(TaiziIntentSchema)

continue · pause · stop · new_requirement · answer_question · skip_clarification · gate_decision · change_request · start_development · start_testing · export_submission · status_query · chat

三级分类策略

  1. 规则快速通道(零成本零延迟):高频词与 ! 硬打断前缀直接命中
  2. LLM 分类:规则未命中时,cheap 档结构化模型按状态机判断;拿不准一律降级 chat(只读调研,不动作)
  3. 状态保底:LLM 不可用时按状态选保守解释 —— 调度永不阻塞用户
A2A 协作方式:Taizi 与其他 Agent 不直接对话。调度模式下产出 TaiziDecision,dispatcher 落成调用并发出 taizi.routed 事件;目标 Agent 产出通过统一事件流(agent.* / tool_call.*)回流。长耗时动作后台执行,Taizi 立即应答。

Opencode Harness · 受治理的代码执行层

开发阶段的代码执行适配层。不是第二套工作流引擎,也不决定项目状态 —— 把已规划好的功能切片交给真实编码助手执行,并把过程重新纳入 OneCompany 的治理与审计。

接口契约(解耦关键)

interface CodingHarness {
  runSlice(slice: SliceSpec, ctx: DevContext): Promise<SliceResult>;
  runReview?(review: ReviewSpec, ctx: DevContext): Promise<ReviewResult>;
  closeProjectSession?(projectId: string): Promise<void>;
}

OneCompany 只依赖这个接口 → 可无缝切换 mimo / OpenCode harness。

九大职责

  1. 隔离编码引擎 · 通过 CodingHarness 接口与 LangGraph 工作流解耦
  2. 每项目独立会话 · 在项目自己的 Git 工作区启动本地 Opencode Server,选择模型层级
  3. 注入 TDD 任务 · Prompt 含切片目标 + 验收检查 + 测试命令
  4. 执行真实 ReAct · 读 / 改 / 跑 / 看失败 / 修正,而非一次性吐代码
  5. 事件桥接(Event Bridge) · 思考片段 / 工具调用 / Diff / 错误 → OneCompany 统一事件
  6. 权限桥接(Permission Bridge) · read/edit/shell/MCP 走 allowlist + 目录边界 + 风险分级
  7. 日志桥接(Log Bridge) · 密钥脱敏,大输出写 artifact,DB 存摘要 + 路径 + 哈希
  8. 收集真实改动 · 从 Opencode 状态 + Git 工作区收集,不信"模型说完成了"
  9. 独立代码审查 · 同一 Harness 启只读 Review 会话,产出结构化裁决

诚实声明

诚实声明:实测在"一句话需求到可运行应用"场景中,单独使用任何 coding agent 都比 OneCompany 更快更强 —— 现在的基模可能不需要如此复杂的编排。OneCompany 更像是用于理解 agent harness 原理的作业。Agent 配置的 model 均采用个人 url 和 key,提交源码时已删除。
