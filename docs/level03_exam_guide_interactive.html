独立项目题目 · Level 03

复杂需求到可验证工程项目的多智能体交付系统

学员需要开发一个多智能体工程交付系统。用户输入复杂业务需求后，系统自动完成计划、架构、代码生成、测试执行、自我评审、缺陷修复和部署说明，最终输出可运行、可测试、可部署的工程项目。

100满分
75建议通过线
4+角色或子 Agent
8+工具能力

1. 题目概览

核心重点：不是直接手写一个固定的 AI 销售线索管理助手，而是实现一个可以根据输入需求自动生成或维护 delivery_app 的多智能体交付系统。

计划与架构

需求梳理、范围边界、风险分析、任务拆解、架构设计。

生成与执行

代码生成、文件管理、依赖安装、测试执行、失败修复。

验证与交付

自我评审、部署说明、验收用例、最终交付报告。

2. 统一测试输入示例

评分人员会把下面这段需求输入到你的多智能体交付系统中，检查系统是否能自动生成或维护 delivery_app。

设计并实现一个 AI 销售线索管理助手。销售人员可以导入客户线索，系统自动判断客户意向等级，生成跟进建议，记录跟进历史。普通销售只能查看自己的客户，销售主管可以查看团队客户数据。系统需要支持客户列表、线索评分、跟进记录、权限控制和数据统计。

3. 用户运行和使用交付工程的流程

输入业务目标

用户输入业务需求、目标用户、期望技术栈或默认约束。

确认计划

智能体生成交付计划、范围边界、风险和任务拆解。

自动实现

系统生成 delivery_app 工程代码、数据模型、页面、接口或本地服务。

测试自检

智能体运行测试或验证脚本，根据失败结果进行修复。

运行验收

用户启动 delivery_app，以不同角色登录或切换身份，完成核心业务流程。

交付报告

系统输出已实现内容、验证结果、已知限制和后续迭代建议。

4. 学员需要实现的系统功能

任务入口

用户输入复杂业务需求，系统创建一次工程交付任务。

计划面板

展示需求梳理、架构方案、任务拆解、优先级和风险。

代码生成与文件管理

生成可运行工程项目所需文件，并记录修改历史。

测试与验证

生成并执行测试脚本或验证步骤，展示测试结果。

自我评审

对功能完整性、权限边界、数据状态、运行路径进行检查。

交付中心

提供运行说明、账号说明、验收用例和最终报告。

5. Agent 架构要求

至少 4 个角色或子 Agent 至少 8 个工具能力 至少 2 个 MCP 或等价服务 必须有测试执行工具 必须有评审或自检阶段
  1. 至少包含 4 个角色或子 Agent，例如 Planner、Architect、Builder、Tester、Reviewer、Reporter。
  2. 至少封装 8 个工具能力，例如文件读写、代码生成、依赖安装、测试执行、数据初始化、权限检查、报告生成、部署配置生成。
  3. 至少接入 2 个 MCP 或等价工具服务，例如文件系统、数据库、代码执行、测试运行、网页检索或容器构建服务。
  4. 交付工程的生成或维护过程必须由多智能体系统完成，不能预先手写固定业务应用后只做包装。
  5. 必须生成 delivery_app 目录，并提供 Dockerfile、docker-compose.yml 或等价一键启动脚本。

角色可以是真正的多智能体，也可以是一个智能体内部的多阶段状态机，但职责边界、输入输出和调用日志必须清楚。

6. 三级交付标准

三级的关键不是页面更多，而是工程闭环更完整。

工程完整性最低要求

  • 有可运行应用，不只是静态页面。
  • 有数据存储：LocalStorage、JSON、SQLite 或数据库。
  • 有角色差异：至少普通销售和销售主管。
  • 有核心业务对象：客户线索、跟进记录、评分结果、建议内容。
  • 有测试或验证脚本。
  • 有 Dockerfile、Compose 或等价一键启动脚本。

验证完整性最低要求

  • 新用户能按说明启动系统并进入测试账号。
  • 普通销售只能看到自己的线索，主管能看到团队数据。
  • 新增线索后，系统能产生评分和跟进建议。
  • 新增跟进记录后，列表、详情或统计中能看到变化。
  • 异常状态有提示，例如空列表、缺少字段、无权限访问。

7. AI 销售线索管理助手最低验收路径

销售进入系统

以销售身份进入系统，导入或新增客户线索。

系统生成评分

根据行业、规模、预算、需求描述等字段生成意向等级。

给出跟进建议

系统给出下一步建议，并说明判断依据。

添加跟进记录

销售添加一次跟进记录，状态在客户详情中更新。

主管查看团队数据

切换为销售主管，查看团队客户列表和统计摘要。

验证权限边界

尝试访问非授权数据，系统应限制或给出清晰提示。

11. 提交后的评分流程

第一步：材料预检

检查压缩包命名、目录结构、必交文件、构建产物、敏感信息、README、环境变量示例、日志和输出样例。

第二步：AI 评测

按 README 执行安装、启动和测试命令，使用统一示例需求检查生成结果和运行日志。

第三步：人工复核

复核关键扣分项和争议项，检查 Agent 阶段、结构化输出、测试证据和交付报告。

12. 核心判断

合格提交

多智能体交付系统 + delivery_app + 测试验证 + 部署材料 + 交付报告。

典型不合格

只有页面样例，没有数据、权限、测试或自检。
